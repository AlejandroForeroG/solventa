# Historical underwriting audit

Acquisition owns `GET /api/v1/underwriting-decisions` and `GET /api/v1/underwriting-decisions/{decisionId}`. The web gateway forwards them after API version negotiation; backend Workers remain private. [OpenAPI](../../../packages/contracts/openapi/v1/underwriting-decisions.yaml) and [synthetic examples](../../../packages/contracts/examples/underwriting-audit.json) define the boundary. The web workspace is `/auditoria`.

## Authorization and audit

Each request calls Identity's existing `authorizeApiAccessV1` once, with a two-second deadline, the sealed web cookie and fixed `underwriting-decisions:read` operation. Identity verifies WorkOS and its active client/session plus an [explicit audit grant](../identity-consent-ecosystem/api-access.md#underwriting-audit-permission). No actor, role, amount or scope comes from query parameters. Partners, mobile users and ordinary web clients cannot read another client's history. An authorized auditor can read all Acquisition underwriting decisions in the selected environment; this is an operational permission, not customer ownership access. An Authorization header is rejected rather than treated as a web credential.

Acquisition validates the RPC response, web actor, UUID principal, operation and bounded lease. The maximum five-second lease is checked before lookup, in the SQL audit insert and before returning data. New requests observe revocation; there is no cross-owner distributed transaction, and no promise that revocation can retract a previously returned copy. No SQL query crosses into Identity.

The owner runtime reads decisions and immutable `offer_revisions`, then inserts `underwriting.audit.read` into its own `audit_events` and commits before release. A collection read uses the auditor's internal client UUID as resource ID and `underwriting_decision_collection` as type; a detail uses its decision UUID, with success or not_found outcome. Search values, financial inputs and cookies are not copied into audit logs. The existing provisional five-year retention applies. A failed lookup, authorization, audit insert or commit returns 503 without decision data. Access denials are durably recorded by Identity's security path. A read does not invent a new underwriting decision, outbox event or financial effect.

## Lookup

List pages contain at most 20 summaries ordered by immutable `decided_at DESC, id DESC`. `next` is the next request's `before` cursor; preserve the remaining filters. UUID cursors identify the exclusive keyset boundary; an absent cursor row gives an empty page. There is no expensive/unbounded total count or client-controlled page size. Migration `0012_underwriting_audit_lookup.sql` supplies the historical order index.

Filters are optional: exact `reference` (decision UUID, offer UUID from immutable revisions, or COT quote code), `product` (vida_hipotecario/flight_delay), `outcome` (accepted/declined/preliminary), and inclusive `from`/`to` calendar dates in America/Bogota. From must not follow to. Unknown, duplicate, empty or malformed values return 400 after authorization. Detail accepts a UUID and no query parameters. More than 100 retained revisions for one decision returns unavailable rather than an unbounded response. Unsupported methods return 405 with Allow: GET. All responses carry traceId/X-Trace-Id, no-store and nosniff; gateway failures retain version headers. Unauthorized is 401, missing permission 403, missing authorized detail 404, invalid input 400 and unavailable dependencies 503.

## Historical explanation

`AuditDecisions` coordinates an audited lookup through a port. `explainDecision` projects only recognized capture fields, omitting arbitrary stored JSON, client identity and provider credentials. Summaries report the original rule/contract versions, outcome, decision time and correlation, plus the quote reference. Product is derived only from the captured rule ID; unknown rules have no inferred product. Detail includes retained normalized inputs, source capture/quality/degradation/confidence, historical consent ID/version and immutable offer prices/revisions. It never reconstructs from today's `offers` projection or refetches providers/current consent. The consent reference explains the past and does not authorize a new use of source data.

The [retained mortgage artifacts](data.md#historical-mortgage-reconstruction) reproduce accepted, declined and preliminary outcomes, integer/decimal pricing and individual checks. The retained flight artifact `academic-flight-1` checks the originally fixed COP 10,000 premium, COP 100,000 payout and 180-minute threshold with its explicitly mocked schedule source, captured flight reference and availability. New flight captures retain those two source-selection facts; older captures report them missing, while an immutable revision can still expose its recorded flight reference. These deterministic versions use no model; `model.status=not_used` is reported only for a recognized artifact without a recorded model. Unknown model provenance stays unknown; recorded model IDs/versions are displayed, and unavailable artifacts remain unsupported.

Reconstruction reports reconstructed, incomplete_capture (with missing keys), invalid_capture, unsupported_rule, unsupported_model or inconsistent_capture. A supported successful reconstruction also compares the capture against the immutable decision's outcome, rule/contract and correlation, and any retained revision premium/currency. It verifies consistency, not cryptographic authenticity. Old mortgage captures lacking income/obligations or identity/affiliation facts cannot be recovered by inference. No historical backfill is performed. Complete historical coverage requires a separate environment-specific inventory; local success is not proof of all deployed legacy records.

## Verification and operation

`npm run check` includes access/HTTP/domain tests, OpenAPI output validation, SPA tests and consumer/provider Pact. `npm run test:audit:sql` creates and removes only a generated disposable local database, applies real owner migrations and runtime grants, and checks expiration/revocation/session binding, suspension, schema isolation, tied-timestamp pagination, date/reference filters, immutable prices, legacy gaps, audited not-found and audit failure rollback. WorkOS/SQL collaborators in Pact are explicit test doubles; SQL smoke uses real SQL. `npm run test:offers:sql` separately writes and reconstructs real mortgage captures through the existing owner flow. Apply/verify migrations using the [migration procedure](../../infrastructure/migrations.md) before deploying. No default real-user grant or external business provider is provisioned by this feature.
