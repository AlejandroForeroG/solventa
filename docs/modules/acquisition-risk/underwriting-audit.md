# Historical underwriting audit

Acquisition owns `GET /api/v1/underwriting-decisions` and `GET /api/v1/underwriting-decisions/{decisionId}`. The web gateway forwards them after API version negotiation; backend Workers remain private. [OpenAPI](../../../packages/contracts/openapi/v1/underwriting-decisions.yaml) and [synthetic examples](../../../packages/contracts/examples/underwriting-audit.json) define the boundary. The web workspace is `/auditoria`.

## Authorization and audit

Each request calls Identity's existing `authorizeApiAccessV1` once, with a two-second deadline, the sealed web cookie and fixed `underwriting-decisions:read` operation. Identity verifies WorkOS and its active client/session plus an [explicit audit grant](../identity-consent-ecosystem/api-access.md#underwriting-audit-permission). No actor, role, amount or scope comes from query parameters. Partners, mobile users and ordinary web clients cannot read another client's history. An authorized auditor can read all Acquisition underwriting decisions in the selected environment; this is an operational permission, not customer ownership access. An Authorization header is rejected rather than treated as a web credential.

Acquisition validates the RPC response, web actor, UUID principal, operation and bounded lease. The maximum five-second lease is checked before lookup, in the SQL audit insert and before returning data. New requests observe revocation; there is no cross-owner distributed transaction, and no promise that revocation can retract a previously returned copy. No SQL query crosses into Identity.

The owner runtime reads decisions and immutable `offer_revisions`, then inserts `underwriting.audit.read` into its own `audit_events` and commits before release. A collection read uses the auditor's internal client UUID as resource ID and `underwriting_decision_collection` as type; a detail uses its decision UUID, with success or not_found outcome. Search values, financial inputs and cookies are not copied into audit logs. The existing provisional five-year retention applies. A failed lookup, authorization, audit insert or commit returns 503 without decision data. Access denials are durably recorded by Identity's security path. A read does not invent a new underwriting decision, outbox event or financial effect.

## Lookup

List pages contain at most 20 summaries ordered by immutable `decided_at DESC, id DESC`. `next` is the next request's `before` cursor; preserve the remaining filters. UUID cursors identify the exclusive keyset boundary; an absent cursor row gives an empty page. There is no expensive/unbounded total count or client-controlled page size. Migration `0012_underwriting_audit_lookup.sql` supplies the historical order index.

Filters are optional: exact `reference` (decision UUID, offer UUID from immutable revisions, or COT quote code), `product` (vida_hipotecario/flight_delay), `outcome` (accepted/declined/preliminary), and inclusive `from`/`to` calendar dates in America/Bogota. From must not follow to. Unknown, duplicate, empty or malformed values return 400 after authorization. Detail accepts a UUID and no query parameters. More than 100 retained revisions for one decision returns unavailable rather than an unbounded response. Unsupported methods return 405 with Allow: GET. All responses carry traceId/X-Trace-Id, no-store and nosniff; gateway failures retain version headers. Unauthorized is 401, missing permission 403, missing authorized detail 404, invalid input 400 and unavailable dependencies 503.

## Historical explanation

`AuditDecisions` coordinates an audited lookup through a port. `explainDecision` projects only recognized decision fields, omitting arbitrary stored JSON, client identity and provider credentials. Summaries report the original rule/contract versions, outcome, decision time and correlation, plus the quote reference. Product is derived only from the captured rule ID; unknown rules have no inferred product. Detail includes normalized inputs, source capture/quality/degradation/confidence, historical consent ID/version and immutable offer prices/revisions. It never reconstructs from today's `offers` projection or refetches providers/current consent. The consent reference explains the past and does not authorize a new use of source data.

### Recovery of omitted historical inputs

The original capture is never updated. `inputEvidence` identifies every input added to its read projection, distinguishing a retained profile, an immutable offer revision and replay of an original fixed mock contract. An absent/empty array means no recovery. Its `field`, `kind`, `reference` and string `version` identify the evidence; profile evidence also includes its original `capturedAt`. The web shows these references beside the decision inputs, and JSON exports retain them.

For mortgage sources named `signal:<scope>`, the owner loads at most twenty matching immutable `risk_profiles` using the original quote's subject, scope, source timestamp and consent reference/version. This uses the existing subject/purpose/time index within the lookup/read-audit transaction. Domain validation additionally requires the signal's scope/timestamp to agree with the profile, validity at decision time, and the decision correlation for a live read. A stored copy may retain its earlier source correlation. No current expiry or current consent replaces historical validity. Different subjects/consents/timestamps cannot supply facts. Conflicting copies or disagreement with a retained input produce `inconsistent_capture` without applying a partial recovery. Identical copies yield deterministic evidence selection. Source bodies and subject tokens are not returned.

The exact old `mock:<scope>` format identifies the original fixed synthetic risk contract retained in `domain/retained-underwriting-inputs.ts`. Its implementation is archived at [revision 689304a](https://github.com/AlejandroForeroG/solventa/blob/689304a8458ee32e112fd52497488c7ce1170c73/backend/acquisition-risk/src/adapters/outbound/mock-risk-signals.ts), Git blob `9efc46a9ba67444a78474d2b112fc99f0da29f07`. This historical simulator always returned COP 8,000,000 income, COP 1,800,000 obligations, score 780, verified identity and active affiliation. Only the exact original input/source shape, supported underwriting version and retained score/ratio/adjustment select `legacy-mock-risk-1`; partial modern captures, changed identifiers or incompatible retained facts do not. No current mock adapter is called. The evidence version identifies the retained revision used for replay; it does not claim that the old capture stored an explicit provider-version field.

The original fixed `MockFlightSchedule` in that archived revision always returned `available:true`. For the exact old flight capture, its UUID comes from agreeing immutable flight offer revisions, while availability is replayed from `legacy-mock-flight-schedule-1`. Both origins are separately disclosed. Missing/conflicting references, changed historical terms and unknown formats cannot be completed through this path. Replayed simulator values are not presented as observations recovered from SQL.

The [retained mortgage artifacts](data.md#historical-mortgage-reconstruction) reproduce accepted, declined and preliminary outcomes, integer/decimal pricing and individual checks. The retained flight artifact `academic-flight-1` checks the originally fixed COP 10,000 premium, COP 100,000 payout and 180-minute threshold with its explicitly mocked schedule source, flight reference and availability. New captures retain these facts directly; the recovery above handles supported older formats with explicit provenance. These deterministic versions use no model; `model.status=not_used` is reported only for a recognized artifact without a recorded model. Unknown model provenance stays unknown; recorded model IDs/versions are displayed, and unavailable artifacts remain unsupported.

Reconstruction reports reconstructed, incomplete_capture (with missing keys), invalid_capture, unsupported_rule, unsupported_model or inconsistent_capture. A successful reconstruction also compares the capture against the immutable decision's outcome, rule/contract and correlation, and retained revision premium/currency. It verifies consistency, not cryptographic authenticity or protection against coherent administrative tampering. Unknown facts are never derived from the result, ratio alone, today's signals or generic defaults. No historical backfill is performed. Complete coverage requires an environment-specific inventory running this version against every retained record; local success is not proof of deployed coverage, and an empty database establishes none.

## Verification and operation

`npm run check` includes access/HTTP/domain tests, OpenAPI validation, SPA tests and consumer/provider Pact. CI runs `npm run test:audit:sql` alongside the existing SQL smoke suites. It creates and removes only a generated local database, applies real migrations/grants and checks expiry/revocation/session binding, suspension, isolation, pagination, filters, immutable prices, legacy gaps, profile recovery/foreign-subject exclusion, preserved captures, audited not-found and audit failure rollback. Domain tests cover conflicting source copies, consent/time/correlation mismatches and original mock replay. The SPA validates/displays optional provenance and accepts the previous response shape. Pact's WorkOS/SQL collaborators are explicit doubles; SQL smoke uses real SQL. `npm run test:offers:sql` separately writes and reconstructs mortgage captures through the existing owner flow. Follow the [migration procedure](../../infrastructure/migrations.md) before deploying schema changes. This recovery uses existing tables/indexes/grants and needs no new migration. No default real-user grant or external business provider is provisioned.
